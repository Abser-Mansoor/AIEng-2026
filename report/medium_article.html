Building a GPT From Scratch: A 3.2M-Parameter Shakespeare Model, Tested, Ablated and Deployed

Every piece of a causal Transformer (attention, masking, multi-head attention, positional encoding, the training loop, a CLI, a REST API and a Docker deployment) written by hand in PyTorch, with no pretrained weights, plus what the experiments actually showed.

1. The problem: what we set out to build

Large language models are easy to use and hard to understand. Calling a hosted API tells you nothing about why attention works, why GPT needs a causal mask, or what the dozens of design choices inside a Transformer actually buy you.

So the goal of this project was to build a small but complete causal language model end to end, without shortcuts:

  • No pretrained checkpoints. No GPT-2, BERT or Llama weights, and no AutoModelForCausalLM. Every weight starts from random initialisation.
  • Every component written by hand: scaled dot-product attention, the causal mask, multi-head split/merge, sinusoidal positional encoding, pre-norm residual blocks, the feed-forward network, the LM head, the sampler and the training loop.
  • Verified, not just run: 23 unit and acceptance tests, a tiny-overfit debugging gate, and controlled ablations.
  • Shipped: a standalone inference module, a command-line tool, a FastAPI service and a Docker deployment answering live requests.

The scenario is deliberately small: a character-level model trained on Tiny Shakespeare that, given a prompt such as ROMEO:, continues it in Shakespeare's style. It is small enough to train in under four minutes on a free Colab GPU, but large enough that every phenomenon worth studying (attention patterns, overfitting, sampling failures, scaling with depth) shows up clearly.

2. Transformer foundations

Why attention? Sequential depth vs. parallel work

A recurrent network computes h_t = f(h_{t−1}, x_t): step t cannot start until step t−1 has finished. A sequence of length T therefore needs T dependent steps, however many cores you have. Attention instead lets every position look at every other position in one batched matrix multiplication. That is O(T²·d) total work, but only one sequential step.

We measured this directly on a Tesla T4 (batch 8, d = 64):

  T   | sequential (s) | parallel (s) | speed-up
------+----------------+--------------+---------
  32  |    0.001646    |   0.000691   |   2.4×
  64  |    0.003053    |   0.001361   |   2.2×
 128  |    0.006679    |   0.000177   |  37.8×
 256  |    0.015723    |   0.000237   |  66.4×

The sequential loop's time grows roughly linearly with T, while the parallel version stays almost flat. Transformers trade sequential depth for parallel work, and GPUs are very good at parallel work. That trade is the main reason Transformers replaced RNNs.

Scaled dot-product attention

Each position produces a query (what am I looking for?), a key (what do I contain?) and a value (what do I pass on?):

Q = X·W_Q        K = X·W_K        V = X·W_V

Attention(Q, K, V) = softmax( Q·Kᵀ / √d_k  +  M ) · V

Q·Kᵀ is a T × T matrix of similarity scores between every query position i and key position j. Dividing by √d_k keeps the variance of the scores near 1 as the dimension grows. Without it, large dot products push the softmax into a near one-hot regime where gradients vanish. The softmax turns each row into a probability distribution, and that distribution weights the values.

The causal mask: what makes it GPT and not BERT

M is the causal mask:

M[i, j] = 0     if j ≤ i   (past or present: allowed)
M[i, j] = −∞    if j > i   (future: blocked)

e.g. T = 4:     j→  0    1    2    3
           i=0  [   0   −∞   −∞   −∞ ]
           i=1  [   0    0   −∞   −∞ ]
           i=2  [   0    0    0   −∞ ]
           i=3  [   0    0    0    0 ]

After the softmax, e^(−∞) = 0, so every future position gets exactly zero weight. This matters because GPT is trained on next-token prediction: position i must predict token i+1. If it could see token i+1, the task would be trivial copying, and the model would learn nothing useful for generation, where the future does not exist yet.

BERT has a different objective: it hides tokens by replacing them with [MASK] and predicts them from both sides. Because the target is removed from the input rather than just placed later in it, BERT can let every position attend to every other position. Same architecture, different objective, different mask.

Multi-head attention

One attention pattern per layer is limiting: a position may need to look at the previous letter and the start of the current word at the same time. Multi-head attention runs H attention operations in parallel on lower-dimensional slices:

head_h = Attention(Q·W_Q^h, K·W_K^h, V·W_V^h)          h = 1 … H,  d_head = d_model / H
MultiHead(X) = Concat(head_1, …, head_H) · W_O

Here is the tensor-shape trace from our implementation (B = 2, T = 12, d_model = 256, H = 8):

input                        (2, 12, 256)    (B, T, d_model)
[1] Q/K/V projections        (2, 12, 256)    (B, T, d_model)
[2] split_heads              (2, 8, 12, 32)  (B, H, T, d_head)
[3] attention weights        (2, 8, 12, 12)  (B, H, T, T)
[3] per-head output          (2, 8, 12, 32)  (B, H, T, d_head)
[4] merge_heads (concat)     (2, 12, 256)    (B, T, d_model)
[5] output projection W_O    (2, 12, 256)    (B, T, d_model)

Positional encoding

Attention by itself is permutation-invariant: shuffle the input and the outputs are shuffled the same way. Nothing in it knows that "dog bites man" differs from "man bites dog". We add fixed sinusoidal position signals to the token embeddings:

PE(pos, 2i)   = sin( pos / 10000^(2i / d_model) )
PE(pos, 2i+1) = cos( pos / 10000^(2i / d_model) )

Each pair of dimensions oscillates at a different frequency, so every position gets a unique fingerprint. A fixed offset between two positions also corresponds to a linear transformation of their encodings, which makes relative position easy to learn. The encoding has zero trainable parameters.

The Transformer block

We use the pre-norm layout of modern GPTs, which trains more stably than the original post-norm design:

x = x + Dropout( MultiHeadAttention( LayerNorm(x) ) )
x = x + Dropout( FFN( LayerNorm(x) ) )

FFN(x) = W₂ · GELU( W₁·x + b₁ ) + b₂        (d_model → 4·d_model → d_model)

The residual connections give gradients a direct path through the network, so each sub-layer only learns a correction to the representation. Attention moves information between positions, and the FFN processes information within each position. The block maps (B, T, d_model) to (B, T, d_model), so blocks stack.

The full model

token ids                        (B, T)
 → token embedding × √d_model    (B, T, 256)
 → + sinusoidal positions        (B, T, 256)
 → dropout
 → 4 × TransformerBlock (causal) (B, T, 256)
 → final LayerNorm               (B, T, 256)
 → LM head (Linear 256 → 65)     (B, T, 65)    logits over the vocabulary

loss = CrossEntropy( logits.view(B·T, 65), targets.view(B·T) )

3. Implementation

Tokenizer

The tokenizer is character-level. The vocabulary is the sorted set of distinct characters in the corpus, which makes it fully deterministic, and has 65 symbols:

"\n !$&',-.3:;?ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz"

'First Citizen:' → [18, 47, 56, 57, 58, 1, 15, 47, 58, 47, 64, 43, 52, 10] → 'First Citizen:'

There are no special tokens: no padding (we always cut fixed-length windows), no BOS/EOS and no UNK. During training an unknown character raises an error. During inference it is skipped (errors="skip"), and the API reports which characters were dropped. Character-level tokenization keeps the vocabulary tiny and needs no trained tokenizer. The cost is long sequences and a model that has to build words letter by letter, which matters later.

Model configuration

vocab_size      65
context_length  128 characters
d_model         256
n_heads         4      (d_head = 64)
n_layers        4
ffn_dim         1024   (4 × d_model)
dropout         0.1
tie_weights     False

Weights are initialised from N(0, 0.02). Following GPT-2, the residual output projections (W_O and the FFN's second layer) are scaled down by 1/√(2·n_layers), so the residual stream's variance does not grow with depth. Token embeddings are multiplied by √d_model so the unit-amplitude sinusoidal positions do not swamp them.

Attention and masking in code

The core of the implementation is a few lines:

def build_causal_mask(T, device=None):
    # True where key position j is in the future of query position i
    return torch.triu(torch.ones(T, T, dtype=torch.bool, device=device), diagonal=1)

def scaled_dot_product_attention(Q, K, V, mask=None, causal=False):
    d_k = Q.shape[-1]
    scores = (Q @ K.transpose(-2, -1)) / math.sqrt(d_k)          # (..., T, T)
    if causal:
        T_q, T_k = scores.shape[-2], scores.shape[-1]
        causal_mask = build_causal_mask(max(T_q, T_k), scores.device)[:T_q, :T_k]
        mask = causal_mask if mask is None else (mask | causal_mask)
    if mask is not None:
        scores = scores.masked_fill(mask, float("-inf"))
    attn_weights = F.softmax(scores, dim=-1)
    return attn_weights @ V, attn_weights

The function broadcasts over any leading dimensions, so multi-head attention reuses it unchanged on (B, H, T, d_head) tensors. It also returns the attention weights, which is what makes the attention inspection in Section 6 possible.

Proving the mask works. We perturbed only the last token of a sequence and measured how much the output at position 0 changed:

Causal (GPT-style) block:          change at position 0 = 0.00000000
Bidirectional (BERT-style) block:  change at position 0 = 0.22196493

We repeated the test on the fully trained model: changing the last character of a 48-character input left every earlier position's logits unchanged (a maximum difference of exactly 0.0), while the last position's logits changed by up to 9.45.

Next-token targets

Targets are the inputs shifted left by one character:

x = ids[s     : s + T]        # input
y = ids[s + 1 : s + T + 1]    # target: y[t] is the character after x[t]

 t | input | target
 0 |  'F'  |  'i'
 1 |  'i'  |  'r'
 2 |  'r'  |  's'
 3 |  's'  |  't'

One forward pass therefore produces T training signals at once, one per position. That is only possible because the causal mask stops position t from seeing y[t], which is the input at t+1.

Training loop

  • AdamW (β = 0.9, 0.95) with weight decay 0.1 applied only to matrices. Biases and LayerNorm gains are not decayed.
  • Learning-rate schedule: linear warm-up, then cosine decay to a floor of one-tenth of the peak rate.
  • Gradient clipping at a norm of 1.0.
  • Logs of training loss, learning rate and throughput (tokens/s) every 50 steps. A validation pass every 250 steps also prints a sample, so you can watch the text go from noise to Shakespeare.
  • Best-validation checkpointing. The checkpoint stores the weights, the model config and the tokenizer vocabulary, so a fresh process can rebuild everything from one file.

Debugging gate. Before any long run, a small model must memorise a single fixed batch. If it can't, something is broken. Our model drove the loss from 4.21 to 0.0002 in 300 steps, which confirms that gradients, target shifting and masking all work together. The same discipline extends to 23 test functions covering shapes, softmax normalisation, mask correctness at every level, the target shift, tokenizer round-trips, checkpoint reloads and causality of the trained model. All 23 pass.

4. Dataset and preprocessing

  • Source: Tiny Shakespeare, the corpus from Andrej Karpathy's char-rnn repository (also published on Hugging Face as tiny_shakespeare). It is a concatenation of excerpts from Shakespeare's plays.
  • Size: 1,115,394 characters in 40,000 lines (about 1.1 MB).
  • Tokenizer and vocabulary: character-level, 65 symbols, no special tokens (see above).
  • Split: the first 90% for training (1,003,854 characters) and the last 10% for validation (111,540 characters). The split is contiguous, not shuffled. A random split would put overlapping windows of the same text in both sets and inflate validation scores.
  • Context length: 128 characters. Training batches are random 128-character windows from the training split.
  • Filtering: none. The text is used exactly as downloaded, with no lower-casing, deduplication or cleaning. With a 65-character vocabulary there is nothing to normalise, and keeping speaker names, line breaks and punctuation is what lets the model learn the play format.

Hardware       Google Colab · NVIDIA Tesla T4 (14.6 GB) · 2 CPU cores

Steps          3,000  → 24.6 M tokens ≈ 24.5 passes over the training split

Evaluation     every 250 steps, 50 validation batches
Checkpoints    minigpt_best.pt (lowest validation loss), minigpt_last.pt (final step)
Seed           1337

The handout suggested a learning rate around 3e-4. We used 6e-4 because a 3M-parameter model with warm-up tolerates a higher rate, and the curve stayed smooth. Because the model sees the corpus about 24 times, overfitting was a real risk. Dropout slows it down, and best-validation checkpointing makes sure any late overfitting would show in the curve without affecting the final model.

Two thirds of every block's parameters are in the feed-forward network, not in attention. That ratio holds for full-scale GPTs too.

Training time

The full run took 3.9 minutes (236.8 s) at an average of 103,789 tokens/s, with a peak GPU memory of 749 MB.

Loss curves

Observation. Both curves start at the uniform-guess baseline, ln(65) ≈ 4.17, as they should for a randomly initialised model. Validation loss falls steeply to 2.25 by step 250, then flattens: 1.74 at step 1000, 1.58 at step 2000, and a minimum at step 2750. At step 3000 it is essentially unchanged.

Interpretation. The model has reached a plateau but has not yet clearly overfit. Validation loss has not turned upward. The training curve sits above validation early on only because it is measured with dropout active.

Attention inspection

We fed the trained model a validation snippet, "d mild behavior,\nAm bold to show myself a forwar", and plotted the attention weights of all 16 heads.

Observations:

  • Every panel is strictly lower-triangular. The causal mask holds in the trained model. An acceptance test confirms the maximum weight above the diagonal is below 10⁻⁶ in every layer.
  • Early layers are local. Layer 0 heads are almost pure diagonal bands. The average weight on the previous character is 0.42, 0.39 and 0.46 for heads 0, 2 and 3. Layer 1 head 3 is the strongest previous-token head at 0.54. These heads mostly learn which letter follows which.
  • Layer 2, head 0 looks at line starts. It shows one bright vertical stripe: almost every character after the line break attends to the same column, the newline. Its previous-token weight is only 0.07, the lowest of all 16 heads.
  • Later layers are more spread out and harder to summarise. They draw on many earlier positions.

The labelled view of layer 3, head 0 shows a clear pattern. Every letter of behavior attends strongly to the space just before the "b". The letters of show attend to the space before the "s", and those of forwar to the space before the "f".

Interpretation: this head seems to track where the current word began. For a model that spells one character at a time, knowing how far into a word it is, and how the word started, is exactly what it needs to finish the word.

A caveat: this comes from a single snippet. The pattern is an observation, and the "word-start head" label is an interpretation that would need many more examples to confirm.

7. Ablation study

We ran three required experiments and two optional ones. To keep them controlled:

  • Only the variable under test changes. Everything else matches the baseline: 4 layers, 4 heads, context 128, d_model 256, dropout 0.1, the same optimiser, schedule and seed.
  • Every run trains for 1,500 steps with the same 8,192 tokens per step. For the context experiment the batch size is adjusted (batch = 8192 / context), so every model sees the same amount of text.
  • The baseline is trained once and shared across experiments.
  • Losses use the same deterministic full-split evaluation as above. Because the runs are half as long as the main model, the baseline reaches 1.693 rather than 1.538.

Experiment 1: depth (2 / 4 / 6 layers)

layers   params    val loss   train loss   gap     time     tokens/s   valid words
  2      1.61 M     1.765       1.585      0.180    59 s    209,920      85.3%
  4      3.19 M     1.693       1.502      0.191   111 s    110,309      89.0%
  6      4.77 M     1.651       1.452      0.199   166 s     73,837      90.0%

Observation. Each added pair of layers lowered validation loss (−0.072, then −0.042) and raised the share of real words. Parameters and training time grow linearly with depth.

Interpretation. Depth is the most effective of the three knobs, but with diminishing returns: the second step gives about 60% of the gain of the first, for the same added cost. The train–val gap widens only slightly (0.180 → 0.199), so the deeper model is genuinely better and not simply memorising. Its validation curve is also still falling at step 1500, which suggests it would gain more from longer training.

Experiment 2: attention heads (2 / 4 / 8)

heads   d_head   params    val loss   tokens/s   peak mem   valid words
  2      128     3.19 M     1.697     114,807    766 MB       85.1%
  4       64     3.19 M     1.693     110,309    798 MB       89.0%
  8       32     3.19 M     1.701      99,959    862 MB       86.3%

Observation. Validation loss is essentially flat. The 0.008 spread is within single-seed noise, and the validation curves (bottom-centre panel) lie on top of each other. More heads made training slower and used more memory.

Interpretation. With d_model fixed, changing the head count does not change the parameter count. It only re-slices the same 256 dimensions into more, narrower heads. At this scale the trade-off between more attention patterns and less capacity per pattern is roughly neutral. The extra cost comes from the larger (B, H, T, T) attention tensors. Four heads gave the best valid-word rate, but with one seed we would not treat that as significant.

Experiment 3: context length (64 / 128 / 256)

context   batch    val loss   tokens/s   peak mem   valid words
   64     128×64     1.675    115,630    766 MB       88.1%
  128     64×128     1.693    110,309    798 MB       89.0%
  256     32×256     1.741     98,360    862 MB       81.6%

Observation. Counter-intuitively, the shortest context gave the lowest validation loss, and the 256-character model was clearly worst, both in loss and in real-word rate. Longer contexts also cost throughput (−15%) and memory (+13%).

Interpretation. More context should never hurt a fully trained model, so this mostly says something about a fixed, short training budget:

  • With tokens per step held fixed, the 64-context model sees 128 independent windows per step and the 256-context model only 32. That gives the shorter model more varied gradients.
  • For character-level Shakespeare, most of the predictive signal (spelling, the current word, the last line) is within a few dozen characters. The extra context beyond 64 has little to offer a model this small after 1,500 steps.
  • Longer windows also mean attention has more positions to spread over, which plausibly takes longer to learn to use. All three curves are still falling, and the 256 model's curve is the steepest at the end.

The honest conclusion: at this budget, longer context did not pay for itself. Whether it would with longer training is an open question this experiment cannot answer.

Optional: learned vs. sinusoidal positions

position encoding   params      val loss   valid words
sinusoidal (fixed)  3,188,736    1.693       89.0%
learned (table)     3,221,504    1.722       87.4%

A trainable position table added 32,768 parameters and was worse by 0.028. With only 1,500 steps, a learned table has to discover position from scratch, while sinusoids provide it for free from step 0.

Optional: decoding strategy (no retraining)

strategy            valid-word rate   repetition rate
greedy (T = 0)          98.3%             39.4%
T = 0.5                 97.6%              0.0%
T = 0.8 (default)       94.5%              0.0%

Temperature trades correctness for variety. Greedy decoding spells best but repeats itself badly. High temperature never repeats but invents words. Top-k = 40 changed nothing at T = 0.8: with a 65-character vocabulary, the 40 most likely characters already hold almost all of the probability mass.

8. Failure analysis

Failure 1: repetition loops under greedy decoding

I am to the common of the country of the country.

KING RICHARD III:
The state of the court of the country,
That I will be the strange of the country's son,
And the state of the seat of the seat of the sea
The sease of the strange of the season of the state,
And she shall be the strange of the seat,
And the state of the seat of the seat of the sea

Evidence: a repetition rate of 0.394 for greedy decoding vs. 0.000 at T = 0.8. Whole lines repeat word for word.

Likely cause: greedy decoding always picks the single most likely next character. Once the text enters a high-probability cycle ("of the seat of the sea…"), the same context produces the same choice, and the loop reinforces itself. A 128-character window makes it worse, because the model cannot see that it already wrote this line a paragraph ago. Sampling breaks the cycle by sometimes choosing a less likely character.

Failure 2: invented words at higher temperature

temperature   words not in the training vocabulary
   0.5              13 / 517   ( 2.5%)
   1.0              39 / 492   ( 7.9%)
   1.3              99 / 448   (22.1%)

examples at T = 1.3:  somerry, overtage, lesing, furny, senatore, nybirty, smoock, treasts

Likely cause: a character-level model has no word list. It builds every word one letter at a time. Raising the temperature flattens the distribution, so plausible but wrong letters get sampled more often, producing non-words that look English (senatore, overtage). A word- or subword-level tokenizer could never output a non-word, because every token would be a known piece.

Failure 3: out-of-domain prompts and unsupported characters

prompt sent:            'The future of AI in 2026: self-driving cars & GPUs'
prompt the model sees:  'The future of AI in : self-driving cars & GPUs'
characters dropped:     ['0', '2', '6']

continuation:
ter;
And thy cowarding law by my cheeks before.
Stir-hard the hause art thy purchased to hearl.

Likely cause: the vocabulary is only the 65 characters in the corpus, which has no digits except "3". Anything else is dropped before the model sees it. Even with valid characters, the model has only ever seen one author's style, so a modern prompt is simply ignored and the model returns to Shakespeare. This is the clearest reminder that a language model's knowledge is bounded by its training data.

Failure 4: different prompts converging on the same lines

With the same seed, the To be, or not to be and The king samples both produce the identical line "My arm that unquest but we than a full of more,". The out-of-domain prompt's continuation also ends with the same two lines as the ROMEO: sample ("Which now thou art self and peace the mild have / A children her years in a kingdom of the house.").

Likely cause: when the prompt carries little information the model can use, its predictions fall back to a few high-probability paths through Shakespeare-like text. Fed the same random numbers, different prompts end up on the same path. The prompt shapes only the first few lines.

9. Engineering packaging

A notebook is not a product. The inference code is packaged separately:

submission/deployment/
  minigpt.py          standalone model + tokenizer + checkpoint loader (inference only)
  generate.py         command-line interface
  api.py              FastAPI service: GET /, GET /health, POST /generate
  minigpt_best.pt     trained checkpoint (12.3 MB)
  requirements.txt    CPU-only torch, fastapi, uvicorn
  Dockerfile          python:3.11-slim, non-root user, built-in health check
  docker-compose.yml  host port 80 → container port 8000, restart unless-stopped

minigpt.py restates the architecture without any training code, so the server never imports the notebook. A test loads the exported checkpoint through this module and checks that its greedy output is token-for-token identical to the notebook model's, so the two copies of the architecture cannot silently diverge.

Requests are validated with Pydantic: the prompt can be at most 500 characters, max_new_tokens 1–500, temperature 0–2 and top-k 1–100. Out-of-range input such as "temperature": 99 gets an HTTP 422 before it reaches the model. The response lists any ignored_characters, so callers know when part of their prompt was dropped. A lock makes the seed and generation atomic, so concurrent requests cannot interfere with each other's random state. Interactive Swagger documentation is served at /docs.

Deployment

The service runs as a Docker container on a Contabo VPS and is live at http://62.169.21.107/ (try /docs). Deployment takes three commands on the server:

git clone https://github.com/Abser-Mansoor/AIEng-2026.git
cd AIEng-2026/submission/deployment
docker compose up -d --build

On this CPU-only VPS, generation takes about 45 ms per character: 100 characters in roughly 4 seconds. Generation is inherently sequential, with one full forward pass per new character, so it cannot use the parallelism that makes training fast. That is the same sequential-vs-parallel trade-off from Section 2, now on the inference side.

Reproducibility

  • A fixed seed (1337) for Python, NumPy and PyTorch. Each sample prompt and each ablation run re-seeds, so results don't depend on execution order.
  • The checkpoint stores the weights, the model config, the training config and the tokenizer vocabulary. A single file is enough to rebuild the model in a new process, and a test checks that a reloaded checkpoint generates identically.
  • The notebook runs top to bottom in Colab, downloads the dataset itself, and writes every figure, CSV and sample to outputs/. Full run logs (configs, hardware, loss history) are saved to outputs/logs/minigpt_run.json.
  • A seed field in the API makes live responses reproducible too.

10. Conclusion

Building every piece by hand and then testing it makes the main ideas of causal language modelling concrete:

  1. The causal mask is what turns a Transformer into a generator. One torch.triu call is the difference between GPT and BERT. We showed it holds exactly: perturbing future tokens changes past outputs by 0.0, before and after training.
  2. Next-token prediction alone teaches structure. With no labels and no notion of words, 3.2M parameters trained for four minutes learned spelling (94% real words), verse layout, speaker turns and archaic grammar, cutting perplexity from 65 to 4.66.
  3. Attention heads specialise in readable ways. Early layers attend to the previous character, while deeper heads track line starts and word starts. This is a small-scale version of the circuits found in large models.
  4. Depth matters more than head count at fixed width. Going from 2 to 6 layers improved loss steadily, with diminishing returns. Changing the head count at the same parameter count did nothing measurable, and more context only pays off with enough training to use it.
  5. Loss is not the whole story. The same model can loop endlessly (greedy) or invent words (T = 1.3) depending on decoding. The tokenizer decides which inputs the model can even see, and a small, single-author dataset sets hard limits on what it can say.

Everything that makes models like ChatGPT work is already present in this model: attention, causal masking, residual depth and next-token prediction. What separates the two is mostly scale (data, parameters and compute) together with tokenization and training techniques built on top of the same core.
